# Руководство по участию в разработке (Contributing Guide)

Спасибо за ваш интерес к развитию **Living Tracker**! Мы ценим любые идеи, улучшения, фиксы ошибок и предложения новых тем или плагинов.

---

## 🧭 Принципы проекта

1. **Local-First & Приватность:** Никаких обязательных облачных бэкендов и телеметрии. Пользовательские данные принадлежат исключительно пользователю.
2. **Легковесность:** Приложение в десктопном режиме должно потреблять минимум ресурсов (~35–50 МБ RAM).
3. **Сочный UI (Juiciness):** Плавные микроанимации, приятные звуковые отклики и эстетика киберпанка.
4. **Надёжность:** Все новые фичи должны сопровождаться модульными и интеграционными тестами (`Vitest`).

## 🛠️ Как внести свой вклад

### 1. Подготовка рабочего окружения
- Убедитесь, что установлены **Node.js 20+** и **npm 10+**.
- Для сборки нативного десктопного бандла потребуется **Rust** (`rustup update`).

```bash
git clone https://github.com/00DaEdRa00/living-tracker.git
cd living-tracker
npm install
```

### 2. Создание ветки
Создавайте ветку с понятным префиксом:
- `feat/amazing-theme` — новая функциональность
- `fix/streak-calculation` — исправление багов
- `docs/update-guide` — документация
- `perf/sqlite-index` — оптимизация производительности

```bash
git checkout -b feat/my-new-feature
```

### 3. Проверка качества кода и запуск тестов
Перед созданием Pull Request обязательно запустите:

```bash
# Проверка типов TypeScript
npm run build

# Запуск полного набора тестов
npm test
```

Все тесты должны проходить без ошибок (`128+ tests passed`).

### 4. Оформление коммитов
Мы следуем спецификации [Conventional Commits](https://www.conventionalcommits.org/):
- `feat(...)`: Новая функциональность
- `fix(...)`: Исправление бага
- `test(...)`: Добавление или обновление тестов
- `docs(...)`: Изменения в документации
- `refactor(...)`: Рефакторинг без изменения логики

### 5. Создание Pull Request
1. Запушьте ветку в свой форк: `git push origin feat/my-new-feature`
2. Откройте Pull Request в ветку `main` основного репозитория.
3. Опишите, какие изменения были внесены и как их протестировать.
